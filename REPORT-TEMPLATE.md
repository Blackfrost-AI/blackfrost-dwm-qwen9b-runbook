# REPORT TEMPLATE — DWM run report

Every completed run produces `REPORT.md` in the workdir, generated by
`run_dwm.py` from the recorded artifacts. It must contain every section
below, in this order. Numbers are never hand-entered; every figure comes
from a stage artifact.

## Evidence hierarchy

`events.jsonl` (append-only gate/event log) and the stage artifacts are the authoritative record. `REPORT.md` is the generated summary of those records.

## Required sections

### 1. Identification
- Method name: DWM — Domain Weight Modification (Blackfrost_AI).
- Explicit statement: this was **not** ablation, **not** abliteration, **not**
  refusal removal, **not** fine-tuning.
- Target model identity: source path, source name, architecture class
  (Qwen 9B family base or fine-tune), dtype, total parameter count.
- Run timestamps (start/end), host summary (GPU model, VRAM used, package
  versions).

### 2. Bank and modes
- Bank file name, SHA-256 (must equal the pinned digest), pair count (32
  harmful + 32 safe), per-mode row counts.
- Thinking modes detected and captured (list with names), template digest.

### 3. Targets
- Decoder layer count, first editable layer, full edit-target inventory
  summary: total count, per-surface counts (attention out / MLP down),
  per-layer coverage.

### 4. Capture results, per round and per mode
- Mean pair-delta norm per layer (tables), peak layer, split-half cosine
  stability.
- Round-over-round direction cosine and norm-ratio telemetry (how the
  signature moved after each edit).

### 5. Edit audit, per round
- Alpha-zero replay result (must be bit-exact identity).
- Per-target: component energy before/after along each applied direction,
  norm-restoration error (must be < 0.002), count edited.

### 6. Capability controls
- For each of the 4 controls × each mode × {baseline, round 0, round 1,
  round 2}: completion flag, exact-match verdict, full transcript.
- Any control failure at any point invalidates the run — the report must
  state this explicitly if it happened.

### 7. Verification
- Changed tensors: count and names, matching the STAGE-1 target inventory.
- Protected tensors: count, bit-identical to source.
- Non-weight files: byte-identical list.
- Source re-fingerprint: unchanged.
- Candidate shard digests.

### 8. Residual signature after the loop
- STAGE-6 final capture summary: what contrast mass remained, per mode.

### 9. Conclusions
- What the loop did, stated from the recorded numbers only.
- What was **not** done: no behavioral benchmark, no deployment, no serving,
  no publication. Candidate fate is the operator's decision.

### 10. Full artifact index
- Absolute paths of every artifact in the workdir.

## Provenance statement (must appear verbatim)

> This run was performed with DWM (Domain Weight Modification), a
> Blackfrost_AI method, using the frozen Blackfrost 32-pair contrast bank,
> on a Qwen 9B-class checkpoint. It was not ablation, not abliteration, not
> refusal removal, and not fine-tuning. All edits were verified
> tensor-by-tensor against the source; non-target tensors are bit-identical;
> the source checkpoint is unchanged.
